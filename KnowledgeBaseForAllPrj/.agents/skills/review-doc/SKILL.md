# Review Documentation

1. Identify the audience, promised scope, authoritative sources, and relevant implementation or interface contracts.
2. Check factual accuracy, contradictions, missing prerequisites, unsafe examples, broken navigation, stale version claims, and ambiguous ownership.
3. Parallelize technical accuracy, consistency/freshness, and readability/link review only when the document set is large enough and all tracks are read-only.
4. Prefer precise, located findings with a proposed correction and source of truth. Separate defects from optional editorial suggestions.
5. Report coverage, limitations, and any source that could not be verified.

Read [references/doc-rubric.md](references/doc-rubric.md) for the review dimensions and output schema.
