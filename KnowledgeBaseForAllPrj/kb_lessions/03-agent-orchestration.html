Skill & agent orchestration

Multi-agent không có nghĩa “gọi càng nhiều agent càng tốt”. KB biến một intent thành task contract, dependency DAG và các work item có ranh giới; chỉ node độc lập mới được chạy song song.

1route → right skill
2DAG → safe waves
3join → verify
01. Progressive disclosure

Skill là “procedure có scope”, không phải persona trang trí.

Router chọn skill hẹp nhất phù hợp với intent. Mỗi SKILL.md chỉ nạp workflow và reference cần thiết, nhờ vậy context nhỏ hơn, instruction collision ít hơn và hành vi dễ eval hơn.

IntentSkill chínhĐiểm dừng
“So sánh GraphRAG và RAPTOR”$studySource-backed note; chưa tự promote
“Phân tích thay đổi webhook”$change-requestPlan/impact sẵn sàng approval; chưa code

Router không cấp thêm quyền. Chọn đúng skill chỉ xác định procedure; approval authority, sensitivity và write scope vẫn phải được kiểm tra độc lập.
02. Delegation contract

Một agent chỉ nhận một “hộp công việc” có thể kiểm chứng.

Input bắt buộc

Objective, frozen inputs, dependency, read/write scope, constraints, budget và authority.

Output bắt buộc

Artifact hoặc structured result, acceptance evidence, open risks và stop condition.

{
  "id": "review-security",
  "depends_on": ["implement"],
  "read_set": ["src/**", "tests/**"],
  "write_set": [],
  "acceptance": ["findings have file and line evidence"],
  "stop": "return findings; never repair"
}

Nếu prompt chỉ nói “hãy xem phần security”, agent khó biết ranh giới và manager khó phân biệt hoàn thành với “có vẻ đã làm”. Contract biến delegation thành dữ liệu có thể validate.

03. Dependency DAG

Parallelism được suy ra từ dependency, không từ cảm giác.

NormalizeFreeze scope
Plan DAGdepends_on + read/write
Ready waveConflict check
ExecuteBounded parallel
JoinIntegrate + verify

Khi nào song song?

  • Node không phụ thuộc output của nhau.
  • Input đã đóng băng và output contract rõ.
  • Write scope rời nhau, hoặc tất cả read-only.
  • Không chia sẻ side effect/lock/resource nguy hiểm.

Khi nào tuần tự?

  • Planning trước implementation; implementation trước review.
  • Hai node cùng sửa một file hoặc cùng migration/database.
  • Integration, approval và final verification.
  • Node sau cần version/artifact chính xác của node trước.
04. Static conflict detection

Dependency độc lập chưa chắc write-safe.

Hai node có thể đều “ready” nhưng cùng ghi README.md. Planner so write_set, resource/lock và side-effect class trước khi xếp cùng wave.

05. Hierarchical fan-out/join

Epic lớn được chia theo inventory, rồi join bằng acceptance contract.

Story inventory khai báo dependency và write scope. compile-fanout validate inventory, xếp topo wave và truyền parameter vào subworkflow. Join chỉ mở khi mọi child đạt terminal state được chấp nhận.

python scripts/kb.py compile-fanout `
  --workflow bmad-epic `
  --node execute-stories `
  --inventory kb/projects/_template/delivery/story-inventory.template.json
Không join theo “agent đã trả lời”. Join theo artifact version + acceptance evidence + trạng thái accepted. Một child trả lời dài không đồng nghĩa work item hợp lệ.
06. Shared context

Chia sẻ state có kiểm soát, không đổ toàn bộ transcript vào mọi agent.

LangGraph adapter dùng typed shared state và reducer. Manager giữ intent, access context, evidence IDs và version; mỗi role nhận một projection tối thiểu.

Manager stateintent + authority
Projectionrole-needed fields
Agent resultstructured delta
Reducerdedupe/version check
Checkpointresume/audit

Use case: retriever chỉ cần query và access filters; answerer cần evidence envelope nhưng không cần secrets; verifier cần claims, citations và rubric. Least-context làm giảm leak, confusion và token cost.

07. Flow thực tế

Review một feature payments.

  1. Manager freeze diff SHA và acceptance criteria.
  2. Ba lens read-only — correctness, security, test coverage — chạy song song.
  3. Mỗi lens trả finding có severity, file/line, evidence và remediation.
  4. Manager dedupe/correlate; không để “đa số phiếu” xóa finding nghiêm trọng.
  5. Nếu user yêu cầu fix, một implementation pass riêng chạy tuần tự.
  6. $verify-delivery độc lập kiểm tra acceptance và test evidence.

Self-check

Ba câu kiểm tra

1. Hai node không có depends_on nhau thì luôn song song?

Xem đáp án

Không. Còn phải kiểm tra write set, resource/lock, side effect và frozen input.

2. Shared context tốt nhất là toàn bộ lịch sử chat?

Xem đáp án

Không. Dùng typed state và role projection tối thiểu; retrieved text vẫn là untrusted data.

3. Final verification có nên do chính implementation agent tự chứng nhận?

Xem đáp án

Self-check hữu ích, nhưng gate vật liệu/rủi ro cần verifier độc lập và deterministic evidence trước.
