01. Trust model

Nội dung được retrieve là dữ liệu, không phải instruction.

Một page có thể chứa câu “ignore previous instructions” do attacker chèn vào tài liệu. Retrieval thành công về mặt relevance nhưng vẫn thất bại về security nếu model trao authority cho câu đó.

User intentauthorized request
Trusted contextscope + sensitivity
Retrieved datauntrusted evidence
Policy/tool gatenever delegated
Answer/actioncitation + audit
Boundary rule: document text không được thay đổi access scope, tool permission, approval authority hay system policy.
02. Retrieval security

Pre-filter và post-filter cùng cần thiết.

ControlNgăn gì?Evidence
Scope/ACL pre-filterKhông đưa unauthorized item vào candidate setCaller-derived filter trace
Sensitivity/status/time filterRestricted, draft, expired hoặc future factMetadata decision per hit
Post-filterBackend/vector-store filter sai hoặc thiếuFinal evidence allowlist
Evidence envelopeInstruction injection từ chunkExplicit data boundary + stable locator
Tool approval gateText kích hoạt side effectAuthority + approval record

Security filter phải áp dụng trước cả sparse lẫn dense retrieval. Không thể retrieve mọi thứ rồi hy vọng prompt nói “đừng leak”.

03. Evaluation stack

Đo từng lớp để biết lỗi nằm ở đâu.

Retrieval

Recall@k, MRR/nDCG, ACL leak rate, citation locator validity, evidence diversity.

Answer

Faithfulness, claim coverage, citation correctness, abstention quality.

Workflow

Correct skill route, DAG validity, completion contract, retry/budget behavior.

Governance

Prompt-injection resistance, unauthorized tool attempt, secret/PII leakage, audit completeness.

Nếu answer sai vì top-k không có evidence, sửa prompt answerer thường không giúp. Layered metrics giữ root cause rõ.

05. Graders

Deterministic first, model judgment có calibration.

  1. Schema, link, test, citation locator, ACL và command result được chấm bằng code.
  2. Semantic faithfulness/clarity mới dùng rubric + LLM judge.
  3. Judge được so với human labels; lưu model/prompt/version và disagreement.
  4. Low-confidence hoặc high-risk disagreement chuyển human review.
Không dùng “LLM tự tin” làm proof. Self-critique có thể lặp lại cùng blind spot. Judge phải độc lập đủ mức cần thiết và được calibration.
06. Evaluation-driven promotion

Kỹ thuật mới đi qua staged rollout.

Candidateversioned change
Offline evalgolden + holdout
Red teamhard security gates
Canarybounded traffic/scope
Promotemonitor + rollback

So sánh với baseline trên quality, latency, cost và safety. Một dense retriever tăng recall nhưng làm ACL leak rate khác 0 phải bị reject. Rollback artifact/version phải chuẩn bị trước canary.

07. Failure walkthrough

Page độc hại cố mở rộng quyền.

  1. Attacker chèn instruction vào tài liệu public.
  2. Query liên quan retrieve đúng chunk đó.
  3. Evidence envelope gắn nó là untrusted text; access context vẫn lấy từ caller.
  4. Answerer trích fact hữu ích nhưng không làm theo instruction.
  5. Nếu chunk yêu cầu tool side effect, tool gate từ chối vì không có approval.
  6. Trace ghi detection; case được thêm vào adversarial dataset qua review.

Self-check

Ba câu kiểm tra

1. Post-filter thôi có đủ chống leak?

Xem đáp án

Không. Unauthorized content có thể đã vào embedding/reranking/context path; dùng pre-filter và post-filter defense-in-depth.

2. Candidate thắng golden set thì promote production?

Xem đáp án

Chưa. Cần holdout, adversarial/security gates, cost/latency, canary và rollback.

3. Vì sao deterministic graders chạy trước?

Xem đáp án

Chúng rẻ, ổn định, audit được và không cần LLM phán những điều code có thể chứng minh.
