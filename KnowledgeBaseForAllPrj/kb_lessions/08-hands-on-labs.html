Setup

Chạy từ root repository.

Set-Location E:\KnowledgeBaseForAllPrj
python --version

Core tool chỉ cần Python 3.10+ và standard library. Mỗi lab có ba phần: command, dấu hiệu pass, và câu hỏi để bạn không chỉ “chạy cho xanh”.

Lab 01 · Knowledge contract

Validate toàn bộ KB và workflow.

python scripts/kb.py validate --json

Pass: exit code 0, JSON summary không có error. Validator kiểm metadata/date/ID/source/link, workflow DAG/state/skill/authority, fan-out inventory và governance datasets.

Thử negative case an toàn

Copy một template ra file tạm ngoài canonical tree, xóa một field rồi đọc schema để dự đoán lỗi. Không cố sửa generated file trong kb/indexes/.

Hiểu đúng: validator xanh chứng minh invariants đã mã hóa, không chứng minh mọi statement trong tài liệu là đúng về domain.
Lab 02 · Regression suite

Chạy deterministic tests.

python -m unittest discover -s tests -v

Pass: mọi test ok, cuối output là OK. Đọc tên test để nhận ra contract nào đang được bảo vệ: workflow conflict, BMAD gates, retrieval filter hay evidence envelope.

Nếu fail: sửa nguyên nhân, không xóa test. Phân biệt failure do fixture stale với behavioral regression bằng cách chạy riêng module/test case được báo.

Lab 03 · Lexical baseline

Tìm knowledge không cần vector database.

python scripts/kb.py build-index
python scripts/kb.py search "multi-agent write conflict"

Quan sát: kết quả có page ID/path/score và trỏ đến orchestration hoặc agent coordination. Đổi query sang “bitemporal valid recorded time” rồi so top hits.

Tại sao cần baseline? Nó rẻ, deterministic và giải thích được. Dense/hybrid chỉ đáng promote nếu eval chứng minh cải thiện so với baseline này.

Lab 04 · Permission-aware RAG

Nhìn evidence envelope và provenance.

python -m integrations.langchain_rag.cli search `
  "GraphRAG multi-hop retrieval" `
  --scopes shared `
  --as-of 2026-11-13 `
  --json

Kiểm tra bằng mắt: mỗi hit có stable page/chunk identity, source/path/heading, status/sensitivity và score. Nội dung phải được biểu diễn như evidence, không như system instruction.

Tiếp tục với scope không tồn tại:

python -m integrations.langchain_rag.cli search `
  "GraphRAG multi-hop retrieval" `
  --scopes unauthorized-project `
  --json

Expected: không trả chunk shared/project trái policy của adapter. Đây là negative test; “không có kết quả” là behavior đúng.

Lab 05 · Fan-out planner

Compile story inventory thành execution waves.

python scripts/kb.py compile-fanout `
  --workflow bmad-epic `
  --node execute-stories `
  --inventory kb/projects/_template/delivery/story-inventory.template.json

Quan sát: wave order tuân dependency; item cùng wave có write scope không xung đột; parameter và completion contract được giữ. Hỏi: story nào có thể song song, và bằng evidence nào?

Lab 06 · Optional LangChain runtime

Kiểm adapter mà không làm canonical phụ thuộc framework.

python -m integrations.langchain_rag.cli check

Core mode cho biết capability nào sẵn sàng. Khi cần LangChain/LangGraph thật, tạo môi trường riêng:

python -m venv .venv
.venv\Scripts\python -m pip install -r integrations/langchain_rag/requirements.txt
.venv\Scripts\python -m integrations.langchain_rag.cli check

Vector index/checkpoint là derived data. Xóa và rebuild được; không được biến nó thành source of truth.

Lab 07 · Learning site integrity

Rebuild atlas và kiểm local links.

python scripts/build_lessons.py
python scripts/build_lessons.py --check
python -m http.server 8000 --directory kb_lessions

Mở http://localhost:8000, thử menu mobile, tìm “RRF” trong Technique Atlas, filter Blueprint/Experimental và đánh dấu hoàn thành bài học. Atlas phải phản ánh đủ danh mục hiện tại trong TECHNIQUES.md.

Definition of understanding

Bạn đã “hiểu sâu” khi làm được gì?

  • Giải thích canonical, episodic, procedural và derived bằng ví dụ của dự án.
  • Dự đoán query cần filter/graph/tree/agentic retrieval nào và failure behavior.
  • Tự vẽ DAG, chỉ ra node nào được song song bằng dependency + write evidence.
  • Chọn Direct/Quick/Epic/Project và giải thích why.
  • Thiết kế golden + holdout + adversarial gate cho một kỹ thuật mới.
  • Truy ngược một answer/change từ outcome về source, workflow và verification.
